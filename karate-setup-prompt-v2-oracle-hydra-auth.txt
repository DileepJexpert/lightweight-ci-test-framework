STEP 5 — IMPLEMENT @EnableAuth BYPASS MECHANISM
────────────────────────────────────────────────────────────────────────────────
This is the most important step. Do NOT modify any existing @EnableAuth annotation
or any existing controller. Add a NEW configuration class that makes @EnableAuth
a no-op when security.auth.enabled=false.

Look at how @EnableAuth is currently implemented in the project. It is likely one of:
  a. A Spring HandlerInterceptor registered in a WebMvcConfigurer
  b. A Spring Security filter or OncePerRequestFilter
  c. A method-level AOP @Aspect

For each case, add the following bypass:

CASE A — HandlerInterceptor approach:
  Wrap the existing interceptor registration in @ConditionalOnProperty:

  @Configuration
  @ConditionalOnProperty(name = "security.auth.enabled", havingValue = "true", matchIfMissing = true)
  public class AuthInterceptorConfiguration implements WebMvcConfigurer {
      private final OryHydraTokenValidator tokenValidator;
      public AuthInterceptorConfiguration(OryHydraTokenValidator tokenValidator) {
          this.tokenValidator = tokenValidator;
      }
      @Override
      public void addInterceptors(InterceptorRegistry registry) {
          registry.addInterceptor(new EnableAuthInterceptor(tokenValidator));
      }
  }

CASE B — OncePerRequestFilter approach:
  @Bean
  @ConditionalOnProperty(name = "security.auth.enabled", havingValue = "true", matchIfMissing = true)
  public OncePerRequestFilter enableAuthFilter() {
      return new OryHydraAuthFilter(hydraIntrospectionUrl);
  }

CASE C — AOP Aspect approach:
  @Aspect
  @Component
  @ConditionalOnProperty(name = "security.auth.enabled", havingValue = "true", matchIfMissing = true)
  public class EnableAuthAspect {
      // existing aspect logic here
  }

The key principle: when security.auth.enabled=false, the bean is simply not created.
Spring Boot skips it entirely. No if/else inside existing code needed.

STEP 6 — WRITE karate-config.js (with Hydra token fetch + auth bypass)
────────────────────────────────────────────────────────────────────────────────
Create src/test/resources/karate-config.js:

  function fn() {
    var env             = karate.env || 'qa';
    var baseUrl         = karate.properties['service.base-url']
                          || java.lang.System.getenv('SERVICE_BASE_URL')
                          || 'http://localhost:8080';

    // Auth mode: set AUTH_ENABLED=false when app started with security.auth.enabled=false
    var authEnabled     = (karate.properties['auth.enabled'] || java.lang.System.getenv('AUTH_ENABLED') || 'true') !== 'false';

    var hydraTokenUrl   = karate.properties['hydra.token.url']     || java.lang.System.getenv('HYDRA_TOKEN_URL')     || '';
    var hydraClientId   = karate.properties['hydra.client.id']     || java.lang.System.getenv('HYDRA_CLIENT_ID')     || '';
    var hydraSecret     = karate.properties['hydra.client.secret'] || java.lang.System.getenv('HYDRA_CLIENT_SECRET') || '';
    var hydraScope      = karate.properties['hydra.scope']         || java.lang.System.getenv('HYDRA_SCOPE')         || 'openid';

    karate.configure('connectTimeout', 5000);
    karate.configure('readTimeout',    15000);
    karate.configure('retry', { count: 10, interval: 250 });
    karate.configure('logPrettyRequest',  true);
    karate.configure('logPrettyResponse', true);

    var bearerToken = 'test-token-auth-disabled';

    if (authEnabled && hydraTokenUrl !== '') {
      // Fetch real Bearer token from Ory Hydra — called ONCE per JVM session, result cached
      var session = karate.callSingle(
        'classpath:karate/features/helpers/get-token.feature',
        {
          hydraTokenUrl:   hydraTokenUrl,
          hydraClientId:   hydraClientId,
          hydraSecret:     hydraSecret,
          hydraScope:      hydraScope
        }
      );
      bearerToken = session.token;
      karate.log('Hydra token fetched successfully for env: ' + env);
    } else {
      karate.log('Auth disabled or no Hydra URL configured — using placeholder token');
    }

    // Inject Authorization + x-request-id on EVERY HTTP request automatically
    karate.configure('headers', function() {
      return {
        'x-request-id':  'auto-' + java.util.UUID.randomUUID(),
        'Authorization': 'Bearer ' + bearerToken
      };
    });

    return {
      env:          env,
      baseUrl:      baseUrl,
      authEnabled:  authEnabled,
      bearerToken:  bearerToken,
      defaultHeaders: {
        'Content-Type':     'application/json',
        'x-correlation-id': 'test-' + java.util.UUID.randomUUID()
      }
    };
  }

STEP 9 — WRITE FEATURE FILES
────────────────────────────────────────────────────────────────────────────────
For EACH @RestController found in Step 1, generate a .feature file.

MANDATORY scenarios for EVERY endpoint:
  1. Happy path — valid request with Bearer token → assert status + response body
  2. Missing Authorization header → assert 401  (only if @EnableAuth present on that method)
  3. Invalid/expired Bearer token → assert 401  (only if @EnableAuth present on that method)
  4. Missing mandatory request header → assert 400
  5. Invalid request body (missing required field) → assert 400
  6. Response schema validation using karate match (#string #number #boolean #notnull)
  7. Response time SLA: assert responseTime < 2000

For POST/PUT endpoints also add:
  8. Idempotency — same Idempotency-Key twice returns same response
  9. Boundary values — min and max field values

For business logic endpoints:
  10. One scenario per decision outcome (APPROVED/REJECTED/PENDING etc.)
  11. Data-driven using Examples: table or karate.read() from testdata/ JSON files

TAGGING RULES:
  Every feature:                @smoke
  Read-only GETs (health):      @smoke @prod-safe @health
  Auth validation (no writes):  @smoke @prod-safe @auth
  Performance checks:           @smoke @prod-safe @performance
  Write operations POST/PUT/DEL: @smoke @qa @sit  (NEVER @prod-safe)
  Business flows:               @smoke @qa @sit @business

EVERY scenario must:
  - Use: * def correlationId = 'test-' + java.util.UUID.randomUUID()
  - Use headers defaultHeaders from karate-config.js (Authorization already injected globally)
  - Never hardcode URL — always use baseUrl
  - Assert HTTP status code AND at least 3 response body fields
  - Use #notnull for dynamic fields (IDs, timestamps, generated values)
  - Never use Thread.sleep — use karate retry or polling helper

EXAMPLE well-formed scenario with auth:

    When method post
    Then status 202
    And match response.loanId        == '#notnull'
    And match response.status        == 'APPROVED'
    And match response.correlationId == correlationId
    And assert responseTime < 2000

EXAMPLE 401 scenario for @EnableAuth protected endpoint:
